# 标题栏与首页的切换菜单：浏览器实测（2026-10-01）

方法：桌面端网页预览（MockBackend，`pnpm --filter @voltip/desktop exec vite --host <ip>`），用 chrome-devtools 在 Chrome 中执行。

- `docs/acceptance/layout/overflow-check.js`：主界面各页、设置的每个分组、设置向导四步，共 20 个页面。视口为 1440×900、1280×800 和最小窗口宽度 960×600，中文和英文各跑一遍。
- `docs/acceptance/layout/menu-check.js`：在首页依次打开九个菜单，即两个预设菜单，以及标题栏和首页的语音模型、麦克风、AI 润色模型菜单。视口为 1440×900、1920×1080 和 960×600，中文和英文各跑一遍。

## 溢出检查

表中数字是有问题的页面数。

| 视口 | 中文 | 英文 |
|---|---|---|
| 1440×900 | 0 | 0 |
| 1280×800 | 0 | 0 |
| 960×600 | 0 | 首轮 7 个，修复后剩 3 个（共 4 处），均为本次改动之前就有的问题（见下文） |

960×600 英文首轮的 7 个页面中：

- 设置向导四步各有 1 处，都是标题栏的麦克风按钮。向导的页名（Setup guide / step 1）比主界面各页长，留给读数的宽度只剩 238 px，设备短名「Fifine K669」被截断，悬停时也看不到全名。修复：麦克风按钮悬停显示设备全名；AI 润色模型按钮在没有模型名时（显示的是原因）悬停显示同样的文字（`apps/desktop/src/features/switchers/SwitcherMenus.test.tsx@regression: the title bar's 麦克风 and AI 润色模型 buttons read whole on hover`）。修复后四步均为 0 处。
- 其余 3 个页面的 4 处出现在本次没有改动的组件里，留作后续处理：
  - 服务商卡片的说明被截断且无法悬停看全文：「语音模型」页的自定义接口卡片 1 处，「AI 模型」页的自定义接口与 Ollama 卡片 2 处。
  - 设置对话框「快捷键」分组页头的读数：1 处。

  以前的溢出检查只在 1280 与 1440 宽度下运行，所以没有发现它们。

## 菜单检查

六组视口与语言的组合下，九个菜单都满足：没有折行的行，没有被截断的行，菜单没有超出窗口。各菜单最右缘在 960 宽英文下为 924 px，最下缘为 574 px（首页「润色模型」菜单）。
