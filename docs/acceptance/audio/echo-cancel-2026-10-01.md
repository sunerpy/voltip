# 混合录音的回声消除：选型与实测（2026-10-01）

用户 2026-09-30 要求在程序里解决混合录制时扬声器声音被麦克风再次录入的问题（docs/dictation.md §22.6）。候选是两个 WebRTC AEC3 的纯 Rust 移植，都在 `deny.toml` 的许可证白名单内，都不需要 C 工具链：

- `sonora` 0.2.0（BSD-3-Clause，MSRV 1.91）；
- `aec3` 0.4.0（MIT OR BSD-3-Clause）。

## 方法

仓库外的一次性比较工程，两个库处理同一组信号，都只开回声消除，降噪和自动增益关闭。

- **信号**：16 kHz 单声道。远端（电脑播放的声音）是英文语音，近端（用户）是中文语音，取自 SenseVoice 仓库的公开测试音频，固定在修订 `2365baeacb507f821a0c8120fcee3d484dba7a07`：`test_wavs/en.wav`、`test_wavs/zh.wav`，后者 sha256 为 `b77f1794…e373`，与 `scripts/smoke-native-cli.ps1` 的固定值一致。
- **回声**：远端经模拟房间到达麦克风。房间包括直达声、四个早期反射和按混响时间衰减的扩散尾音，再加上延迟。共四组条件：

  | 延迟 | 混响时间 | 回声相对人声 |
  |---|---|---|
  | 30 ms | 0.25 s | −6 dB |
  | 60 ms | 0.3 s | 0 dB |
  | 120 ms | 0.4 s | −6 dB |
  | 60 ms | 0.3 s | +6 dB |

  底噪 −66 dBFS。人声有效值约 −26 dBFS。
- **时段**：24 秒。0–12 s 只有远端，12–18 s 双讲，18–24 s 只有近端。
- **指标**：
  - 回声衰减：只有远端的 3–12 s 内，输入与输出的能量比。
  - 只有近端时的人声损失：18.4–23.6 s 内，输入与输出的能量比。
  - 双讲时的人声损失：同样的信号带人声、不带人声各处理一遍，两次输出之差就是被放过的人声，用它的能量与人声能量相比。
- **耗时**：本机 release 构建，每 10 ms 帧的平均处理时间。

## 结果

| 指标 | sonora 0.2.0 | aec3 0.4.0 | 门槛 |
|---|---|---|---|
| 只有远端时的回声衰减 | 36.5 / 43.6 / 36.5 / 46.3 dB | 32.1 / 26.4 / 27.1 / 35.6 dB | ≥ 20 dB |
| 只有近端时的人声损失 | 0.24 dB | 0.44 dB | ≤ 3 dB |
| 双讲时的人声损失 | 1.58 / 2.18 / 2.09 / 3.09 dB | 1.92 / 2.22 / 2.44 / 3.36 dB | 不被抹掉 |
| 每 10 ms 帧耗时 | 约 175 µs | 约 195 µs | < 1 ms |
| 每帧分配内存（稳定后） | 约 35 次，都在采集路径 | 约 68 次（渲染 8 次，采集 60 次） | — |
| 依赖 | 自己的子 crate（aec3、agc2、common-audio、fft、ns、simd） | rustfft、num-complex、crossbeam-channel、postcard、serde、hound 等 | — |

另有一项对照：关掉高通滤波后，sonora 在只有近端时的输出就是输入延迟 128 个样本（8 ms）的结果，最小二乘拟合残差为 −45 dB。打开高通滤波时的差异来自滤波器的相位，不是失真。

## 结论

选用 `sonora`：
- 回声多消 8–17 dB；
- 人声损失与 aec3 相当；
- 依赖更少，接口沿用 WebRTC APM；
- 下载量约 42 万次，aec3 约 4 万次。

两者都会在每帧处理时分配内存，所以 Voltip 把回声消除放在单独的混音线程，不在音频回调里做（docs/dictation.md §22.6）。

## 仓库内的测试（同日）

- **合成信号**：`crates/voltip-audio/tests/echo.rs` 用合成的类语音信号，不需要任何录音文件。三组房间的实测：

  | 延迟 / 混响 / 回声相对人声 | 回声衰减 | 只有人声时的损失 | 双讲时的损失 |
  |---|---|---|---|
  | 30 ms / 0.25 s / −6 dB | 36.9 dB | 0.53 dB | 2.09 dB |
  | 60 ms / 0.3 s / 0 dB | 35.8 dB | 0.42 dB | 3.33 dB |
  | 120 ms / 0.4 s / +6 dB | 30.6 dB | 0.30 dB | 5.74 dB |

  测试的门槛是 20 dB、3 dB 和 8 dB。双讲的门槛留出余量，是因为不同处理器走的 SIMD 路径不同，结果会略有差异。
- **耗时**：release 构建下每帧平均 192 µs，p99 722 µs，最大 762 µs（`a_frame_takes_well_under_a_millisecond`，`#[ignore]`）。
- **Windows SSH 主机**（`scripts/windows-remote.sh gate echo`，release，提交 ba4e8ab）：
  - 三组房间消掉 36.9 / 32.5 / 29.9 dB，只有人声时损失 0.53 / 0.42 / 0.30 dB，双讲时 2.14 / 3.00 / 5.86 dB。与本机略有差异，因为两台机器走的 SIMD 路径不同。
  - 每帧平均 332 µs，p99 1.32 ms，最大 1.44 ms。
- **真实声音服务器**：`crates/voltip-audio/tests/loopback.rs` 在 PulseAudio 16 上运行（`#[ignore]`）。测试把默认输入临时指向空 sink 的监听源，让麦克风听到的正是扬声器播放的内容，然后录三次：

  | 录制方式 | 电平 |
  |---|---|
  | 只录电脑声音 | −22.2 dBFS |
  | 混合，不消除回声 | −21.0 / −21.5 dBFS |
  | 混合，消除回声 | −24.9 dBFS |

  消除后只剩 −3 dB 的电脑声音（两路各以 −3 dB 混入），麦克风录到的那一份已被去掉。这台无头机器上，经 ALSA 的 PulseAudio 插件录制的麦克风流只有实时的约 60%，混合录音的时长因此短于墙钟时间。
